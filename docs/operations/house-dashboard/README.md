# House dashboard

Versioned source for Loch Highland's live Home Assistant dashboard. HA remains managed through HA-MCP; these files are not consumed by mise reconciliation or a push-triggered deployment.

## Files and live locations

| File                         | Live location                                                                                                                                              |
| ---------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `dashboard.json`             | Storage dashboard `house-atlas`, view `home`, title **House**                                                                                              |
| `house-atlas.js`             | `www/house-atlas.js`, module resource `b917dcc7055c41c2bbe8167df0727d30` at `/local/house-atlas.js?v=<sha256 prefix>`; registers `custom:house-atlas-card` |
| `house-atlas-theme.yaml`     | `themes/house_atlas.yaml`, theme **House Atlas**                                                                                                           |

Open `/house-atlas/home` on the current HA address. House is the system default dashboard. The global theme carries Copied City and City Ruins, the light and dark palettes the terminals and editors use; the user profile must use the backend-selected theme and Auto mode to follow the device appearance. `house-atlas-theme.yaml` is generated by `bootstrap/capabilities/terminal-theme/city-ruins/render.py`: change the palette there, rerun it, and apply the result.

## Dependencies and behavior

- Requires HA 2026.11's contextual name formatter; tested with HA 2026.11.0 and HACS **ha-floorplan v1.1.5**, registered as a module at `/local/community/ha-floorplan/floorplan.js?v=188323494115` (resource `49c6783e7fb24c1ba63688c9bf2d8f83`).
- Fixture labels use `hass.formatEntityName(state)` rather than stripping room prefixes from `friendly_name`. Hue scene buttons request only the entity name because room focus already provides context. Keep entity IDs stable; device names describe objects, entity names describe functions, and registry areas supply location. Card-specific labels in `dashboard.json` remain presentation overrides.
- Native HA tiles show the room's original lighting groups directly below its scenes, with individual tiles only where no groups were configured. Individual fixtures remain on the map and have compact hold/right-click dialogs, anchored on wide layouts and bottom-aligned on narrow layouts; More controls opens native HA details. The frontend entity/device registry interfaces are not stable public custom-card APIs, so check them after HA upgrades. No Bubble Card or card-mod dependency.
- `dashboard.json` contains the final geometry, door openings, labels, and explicit entity controls. Edit it directly; no generator is required. Rooms using `hueScenes` must have `id` values matching HA area IDs. Basement is one HA area and Hue room; its `partitions` path preserves the internal walls.
- `room.lights` lists individual bulbs for status and placement. `room.controls` selects displayed light-group controls. `room.group` is the optional whole-room control; room and house power actions use it, otherwise the distinct groups resolved from `room.controls`, with individual lights only where ungrouped. `room.appliances` adds toggleable tiles beside the room's primary entity; Kitchen lists the espresso machine's power switch. `room.scenes` lists curated scene buttons; Living Room keeps its combined scripts. Without it, `room.hueScenes` populates Hue scenes by entity/device area assignment. Hue scenes call `hue.activate_scene` with `dynamic: true`; scripts and other scenes call `<domain>.turn_on`.
- Tapping unoccupied room space opens its focused map and controls directly. Empty rooms do nothing and are not keyboard buttons. Room list entries open the same focus. The front door toggles lock/unlock directly, without confirmation; moving, jammed, or unavailable locks do not toggle. Hold/right-click opens controls. The basement lock symbol still opens native details. Floor and room selection stay local to each browser.
- Placements with `door: "front"` or `door: "garage"` use architectural shapes instead of device icons. The front door is a double leaf, with the right-hand leaf opening inward (viewed from outside); the drawn swing describes its construction, not a measured open state. Its separate glyph reports lock state. The garage spans both cars: rigid panels translate horizontally through a clipped doorway rather than changing width. Closed, only a narrow edge is visible; fully open, the overhead door covers 100 of the garage's 170 map units, just past halfway. Translation follows reported `current_position`, falling back to the open/closed state when position is absent. Its closed/open/moving glyph sits on the visible panel. The front-door hold panel opens with the native live camera card, then lock controls; there is no separate camera marker.
- The Garage Door tile is one button: a tap anywhere calls `cover.toggle`, which opens a closed door, closes an open one, and stops a moving one. The frontend's own `toggle` action would close a moving door instead. Its icon follows the state, with arrows while moving. The map's architectural door visualization reports state without a duplicate text caption; accessible device labels retain the state.
- Room rules use `double_tap_action: false` for immediate selection. An `{ action: "none" }` object still enables Floorplan's 400 ms double-click detection delay.

Scenes appear in one row below the focused room, never scattered beside the whole-floor map. The row shows up to three scenes, with overflow browsing that sends no commands. Scene buttons are commands, not persistent active-scene indicators. Floor names appear in the tabs without repeated headings.

Light and appliance tiles toggle on a tap anywhere on the tile or icon; holding either opens native HA details. The Garage Door tile also opens details on hold without operating the door. Map switches, including the espresso machine, use the same tap-to-toggle and hold/right-click-for-details distinction. Unavailable map switches do not toggle. Thermostats, media players, and the basement lock open details on either map gesture; the basement lock retains explicit Lock/Unlock buttons in room controls. Scenes run their named command, room backgrounds open room focus, and room-background holds retain their scheduled quick actions.

### Room focus

The card's `placements` maps entity IDs to `{floor, room, x, y}` in floor-plan SVG coordinates. Each light also requires an `icon`; optional `glowPercent` ranges from 0 to 100, defaulting to 100. Saved symbols include Hue fixture silhouettes and the repo-owned full-height floor-lamp shade; the eight basement lights use bare bulbs. Hue paths are embedded in the card, so no icon pack needs installing. They are unchanged paths from [Hue Icons](https://github.com/arallsopp/hass-hue-icons/tree/4604f9ad40f251f829da9ac27a82dac74666742c), by arallsopp, under [CC BY-NC-SA 4.0](https://creativecommons.org/licenses/by-nc-sa/4.0/).

Tap/click, Enter, or Space toggles the fixture's existing lighting group, or the individual light where no group is configured. Membership comes from the `entity_id` attributes of the HA entities in `room.controls`; `room.group` supplies the whole-room fallback. No helper memberships are duplicated in dashboard configuration. Hold for 450 ms, right-click, Shift+F10, or the Context Menu key opens the individual light's supported brightness, color, and white-temperature controls without toggling. Movement, scrolling, and pointer cancellation cancel a hold; sliders send on release. No global adjustment mode changes tap behavior. Map and dialog text suppress native selection/callouts during holds. Escape or Close dismisses controls and restores focus.

Color adjustment uses HA's `ha-hs-color-picker`, loaded through `loadCardHelpers().importMoreInfoControl("light")`. Tap or drag the wheel to choose a color; only the committed `value-changed` sends `hs_color`, converting saturation from 0–1 to HA's 0–100. White temperature is a separate warm/cool slider. The wheel is an internal frontend component checked against frontend 20260826.7 (HA Core 2026.9.2); verify its properties/events after upgrades. More controls remains available while the wheel loads and provides the native alternative.

Both phone and desktop maps have invisible 56 px device targets around fixed symbols, without hover discs. One candidate acts immediately; overlapping targets open a circular magnifying lens without sending a command, including across room boundaries. If all candidates toggle the same light group, a tap acts immediately instead; hold/right-click still resolves the individual fixture. The lens centers on the candidate icons, constrained to fit the viewport, and copies the rendered map SVG and its computed styles so walls, openings, stairs, deck patterns, and parked cars match the source. Glows continue to follow reported state. It enlarges spatial separation while retaining usable icon sizes, without a heading, instruction, or Close button. Names and room identities remain in accessible labels and hover titles. Coincident or still-too-close anchors use separated, named choices inside the lens. Outside tap or Escape dismisses it without operating devices. Background taps on the main map still navigate rooms. Keyboard and assistive activation already identify a device and need no chooser. Main-map symbols never move, and no leader lines or anchor dots are drawn. Pointer-opened dialogs focus the dialog itself; keyboard navigation retains visible button focus.

Narrow layouts (1000 CSS px or less) present light controls as bottom sheets; wider layouts anchor them beside the target. The magnifying lens stays over its map location at both widths. Focus keeps faint neighboring outlines for context and an always-visible group control list below the scene row, without a disclosure toggle. Every lit room has a 44 px power target on both full and focused maps, positioned by `room.power: [x, y]` or above its label. It turns the room off if any light is on; otherwise it recalls the usual scene from `hold.scenes`, using the same house-time schedule as a room hold. Rooms without a scheduled scene power their groups on. An entirely unavailable room disables the switch. House-wide off is hidden while a room is selected. Switch-only lamps have power controls, not a fictitious brightness slider. Pointer interactions and returning browser focus do not draw button outlines; keyboard navigation retains them.

Basement is one dashboard room, HA area, and Hue room with eight individual bulbs and four Hue zones: Under Main Bedroom, Under Living Room, Entryway, and Under Kitchen. The zones' bridge names and HA light IDs begin with Basement / `light.basement_`; individual bulb IDs carry that prefix too. A bulb tap toggles its zone; hold still addresses the bulb. Room power uses the native `light.basement` group for all eight. The walls, openings, and basement lock (`lock.basement_door`) remain in place. The lock's diagnostic IDs use `basement_door_lock_` to distinguish them from its separate contact sensor. The basement auto-lock automation references the renamed lock. Infrastructure devices belong to the same Basement area. These Hue groups currently have no scenes. Little Room is architectural space within Basement; Covered Deck stays separate. Apple Home also has one Basement room, preserving its four two-bulb groups and existing accessories with distinct bulb names; the four empty old rooms were removed. Google Home room assignments remain unverified and require its mobile app; HA area changes do not migrate them.

The versioned light positions include small alignment corrections to near-matching rows and columns in Living Room, Main Bedroom, Thurston Office, and the basement rooms under Kitchen, Living Room, and Main Bedroom. Deliberate offsets are preserved; the doors sit on their architectural openings. The placement studio's raw save remains the reference before alignment.

Glows follow reported RGB color and brightness. Optional placement `fallbackColor: [r, g, b]` supplies RGB bytes only when the light reports no color; otherwise the fallback is neutral. Living Room's two switch-only floor lamps use warm ivory `[255, 221, 176]` (`#ffddb0`) as a perceptual illustration of their provisional 2700 K bulbs, not a physical Kelvin conversion. [DOE's LED color guidance](https://www.energy.gov/sites/prod/files/2016/08/f33/led-color-characteristics-factsheet.pdf) describes chromatic adaptation and the variation within a nominal CCT; the selected swatch is our visual calibration, not a DOE recommendation. Hue's reported colors are unchanged. Off/unavailable lights emit no glow, and unavailable symbols are dashed rather than presented as off. There are no on/off dots beneath light symbols. Screen blending inside an isolated, opacity-bounded room field makes overlap independent of fixture drawing order. Symbols keep their individual source color. `glowPercent` changes only the illustration, never service payloads: Living Room's Signe pair starts at 45 versus 100 for the shaded floor lamps, pending visual calibration. These are not lux measurements.

Hue telemetry is not a continuous view of physical animation. Two 60-second live samples of Main Bedroom's dynamic Pensive scene showed HA matching bridge-reported colors in 123/124 and 124/124 samples respectively, but the second window reported fixed colors/gradient points despite dynamic playback. The card follows available state updates and does not synthesize animation or optimistically hide clicked lights. HA group helpers forward commands to individual lights; native Hue groups use one bridge group command. Their members can consequently report changes at different times. Back returns from room focus to the whole floor. Basement's floor-view hold toggles all basement lights; other room holds remain unchanged.

Main Bedroom's **Ambient light** is its native Hue room group, exposed as `light.main_bedroom_ambient_light`, combining the three fluff lamps and cloud painting. Breakfast Nook's **Lights** is its native Hue room group `light.breakfast_nook`. These grouped controls are directly visible in room focus; individual lights remain visible on the map.

These groups are prerequisites, not created by these exports. Hue owns the Hue-only groups; only the two non-Hue floor lamps need an HA helper:

| Entity                                | Owner    | Members                                                                                    |
| ------------------------------------- | -------- | ------------------------------------------------------------------------------------------ |
| `light.living_room_ambient_light`     | Hue room | Signe Floor Light Left, Floor Right, Wall Wash Right                                       |
| `light.thurston_office_desk_lights`   | Hue zone | Desk Lamp Left and Right                                                                   |
| `light.thurston_office_ambient_light` | Hue zone | Wall Wash Left and Right                                                                   |

The Living Room scene scripts are also prerequisites. Each runs `hue.activate_scene` with `dynamic: true` in parallel with setting `light.living_room_floor_lamps`: `script.living_room_evening_lights` plays Autumn gold with the lamps on, `script.living_room_late_night` plays November haze with them off, and `script.living_room_tokyo` plays Tokyo with them off. Neither branch waits for the other; the non-Hue lamps still use their own transport. Hue stores brightness per scene, so the scripts leave it to the Hue app.

`automation.living_room_hue_companion_lamps` also follows the Hue scene selector and native `light.living_room_ambient_light` group's power state, so Hue-app changes still control the companion lamps without recalling a scene.

## Press and hold

Holding a room on the map for 400 ms runs its `room.hold` quick action, with a pulse on the room and a haptic in the companion app, and does not open the room. Rooms without `hold`, such as Kitchen, ignore it. The card refuses to load an invalid `hold`.

| `hold.action` | Requires          | Does                                                                                              |
| ------------- | ----------------- | ------------------------------------------------------------------------------------------------- |
| `lights`      | `room.lights`     | Turns them all off if any is on; otherwise turns them on, or runs the current `hold.scenes` entry |
| `lock`        | a `lock.` entity  | `lock.lock` only; a hold never unlocks                                                            |
| `toggle`      | a `cover.` entity | `cover.toggle`                                                                                    |

`hold.scenes` lists `{from, entity}` for `scene.` or `script.` entities. Each entry runs from its `HH:MM`, in HA's time zone, until the next; the latest carries past midnight. Living Room plays Tokyo from 00:00, Evening lights from 06:00 and Late night from 21:00; Thurston Office plays Blossom from 06:00 and Tokyo from 18:00; Screened Porch plays November haze and Main Bedroom Pensive. Basement's hold toggles all basement lights; its lock remains independently addressable.

Two Floorplan behaviours shape this. Its stylesheet forces `pointer-events: all !important` on every SVG element, so the card restores pass-through for the cars, bins and stairs with a more specific rule; otherwise presses on them miss the room. And it fires the tap action on release even after a hold, so the card ignores a tap on a `hold` room when the press lasted 400 ms.

## House controls

The card's `override` key names an `input_boolean` that pauses the door automations; the card refuses to load without it. `input_boolean.door_automations_override` is a prerequisite helper, not created by these exports. `automation.garage_close_after_departure`, `automation.front_door_auto_lock_after_closed`, and `automation.basement_door_auto_lock_after_closed` each require it off and also trigger when it turns off, so resuming locks and closes anything left open.

Controls split by lifetime. Suggested actions appear only while relevant, above the floor tabs and below the map on phones; the strip disappears when neither applies:

- **Turn all off** shows outside room focus while any light in a room's `lights` list or in `lamps` is on and turns them all off in one `light.turn_off` call.
- **Secure** shows while a room's `lock.` entity is not locked or its `cover.` entity is not closed. It locks or closes only those.

House-wide settings live in **Control Room**, opened from the header beside Room list. It replaces the floor tabs and map with a control desk: one instrument per `thermostats` entry, then Auto-lock & close, then a full-width Lamps instrument when `lamps` is set. Phones stack them in one column. The suggested actions stay visible above it.

- Each thermostat shows its measured temperature as a bar above a rule, without text labels, and its target as a matching bar in the accent colour below the rule's numbers, joined to the rule by a hairline drawn over the numbers. Drag the target to set it; it sends on release. Its grab area is 44 px wide and spans the hairline and bar, larger than either mark. The ‹ and › buttons at the ends of the rule wait 700 ms for further taps, then send one `climate.set_temperature`; arrow keys on the focused target do the same. The target stays faded until HA reports the new setpoint, or for 30 seconds. A dropdown beside the `hvac_action` in the header lists the entity's `hvac_modes` and calls `climate.set_hvac_mode` on change. An unavailable thermostat shows only its header, "Unavailable", and when it last reported.
- Lamps holds a native tile per `lamps` entry, with a brightness slider; tap the tile to toggle power and hold for the full colour picker. A lamp with `sceneArea` gets the same Hue scene buttons as a room, drawn from that HA area. It is for lights with no fixed room, such as `light.portable_lamp`, which has no HA area of its own but plays the scenes of the Hue Home room (area `home`).
- Auto-lock & close lists the doors and a single button. Control Room is the only place to **Pause** the override; the button then reads **Resume**. While paused, an "Auto-lock paused" stamp sits on the map; dragging it off, or **Resume** in Control Room, turns the override off.

The card's `thermostats` key lists `{name, entity}` pairs for `climate.` entities; the card refuses to load without at least one. The optional `lamps` key lists `{name, entity}` pairs for `light.` entities, each with an optional `sceneArea` HA area id. `thermostatScale` is the `[low, high]` whole-degree range every rule shares, so the instruments line up; each degree gets a labelled tick, and targets cannot be set outside it. A reading outside the range pins to the nearest end. At the narrowest layout, a window just wide enough for the side-by-side desk, the rule fits about ten labelled degrees; 66–76 fits everywhere.

## Doorbell polaroids

`room.doorbell` on Foyer names the Nest doorbell's `camera`, its `ring` and `motion` event entities, the `snapshots` media folder, and the `pin` point in map coordinates. The Foyer panel opens with a live `picture-entity` feed.

Each ring or motion event pins a polaroid at the front door on the Main floor, newest three stacked. Rings carry a RING stamp; motion captions name the event type. A polaroid fades with age and expires 15 minutes after its event. Tap one to open its snapshot full screen, with buttons for the Foyer's live feed and for dismissal; or drag it off to dismiss it. Dismissals are stored per browser in `localStorage` under `house-atlas-dismissed`, keyed by `nest_event_id`.

Nest gives HA no event media for this doorbell: it advertises `CameraEventImage`, but SDM rejects `GenerateImage` for WebRTC-only cameras ("camera not supporting RTSP protocol"), and it lacks `CameraClipPreview`. The photo instead comes from Scrypted. On each event the `Front door snapshot` automation calls `shell_command.front_door_snapshot`, declared in HA's `configuration.yaml`, which has ffmpeg save the first frame of a fresh connection to Scrypted's Rebroadcast RTSP stream (`rtsp://10.10.40.43:33159/85272fedf846f071`) as `/media/doorbell/<kind>-<slot>.jpg`, where `<slot>` is the event's epoch second modulo 1000. Nest events reach HA about 3 seconds after they happen, too late for the newest frame to still show a passing person, but a fresh Rebroadcast connection replays Scrypted's prebuffer from its last keyframe, about 2.6 seconds back, so the frame lands near the event moment. Slots bound storage to 2000 files; the card resolves the slot through `media_source/resolve_media` and retries for 10 seconds until the file is no older than its event. Until then, or without one, the polaroid shows a doorbell icon.

## Pickup reminder

The Main-floor garage has a small indicator along its bottom edge near the left corner, positioned by `room.pickup.position` in map coordinates. The parked cars sit above it so both bins remain visible together. It never changes the map's size or position. Green indicates garbage; blue indicates recycling. Only the bin symbols are visible; the pickup description remains available to screen readers. No dismissal or bin-movement detection is implied.

`sensor.trash_pickup_reminder` owns the schedule: `tomorrow`, `today`, or `hidden`, with `pickup_date` and `pickup_types` attributes. It selects today's pickup before tomorrow's from the provider-backed `sensor.trash_pickup_current_pickup` and `sensor.trash_pickup_next_pickup`. HA's local date determines the two-day window; `now()` makes HA reevaluate at each minute boundary without a browser timer. Unavailable provider data makes the reminder unavailable, which the map hides. `calendar.trash_pickup` remains the provider's calendar, not a visibility switch.

ReCollect polls once a day, and HA does not retry a failed poll before the next one, so a poll during an internet outage would leave the reminder unavailable for a day. `automation.trash_pickup_retry_failed_refresh` requests a refresh every 15 minutes while `sensor.trash_pickup_next_pickup` is unavailable. A failure at HA startup needs no help: the config entry retries setup itself.

The sensor uses YAML because the Template Helper config flow cannot define custom attributes. Apply the file's list under `template:` through managed YAML editing, preserving any other template entries, and run `homeassistant.check_config`. The first template integration requires an approved Core restart; subsequent edits use `template.reload`. The sensor is active and verified against live provider data.

Browser checks should cover both streams, each stream alone, hidden/unavailable states, and a sensor first appearing after the map loads. Inject preview states only into the browser card's `hass` object, never into the live provider entities.

## Maintenance

Before editing, read the live dashboard, resources, and theme through HA-MCP and compare them with these copies so newer live changes are not overwritten. Use `ha_config_get_dashboard`, `ha_config_list_dashboard_resources`, and `ha_config_get_yaml` for theme key `House Atlas` in `themes/house_atlas.yaml`; read the card itself with `sudo incus exec home-assistant -- cat /mnt/data/supervisor/homeassistant/www/house-atlas.js`.

The card is a `/local` file rather than an inline `data:` resource so the companion app can cache it: HA serves `/local` with a 31-day `max-age`, which is why the resource URL carries a `?v=` content hash. Apply approved changes: push the card with `sudo incus file push house-atlas.js home-assistant/mnt/data/supervisor/homeassistant/www/house-atlas.js`, then point the existing resource at the new hash with `ha_config_set_dashboard_resource(resource_id=…, url="/local/house-atlas.js?v=<first 8 of sha256sum>")`. Through HA-MCP, update the storage config with `ha_config_set_dashboard`, and the theme through managed YAML editing with diff confirmation and validation. Refresh the best-practices read-receipt required by gated tools. The instance already includes `themes` through `frontend.themes`; reload themes and select House Atlas for both backend light and dark defaults when restoring it. Refresh the browser after JavaScript changes.

Verify light/dark phone and tablet layouts, all four floors, doorbell polaroids with injected event states and slot files, room-list navigation, scene updates, and sheet dismissal versus scrolling/slider interactions. Intercept service calls when testing lock buttons; do not operate physical locks as a smoke test. Compare the resulting live configuration with these files before committing.

## Placement studio

`placement.html` and `placement_server.py` are a standalone layout editor, not a deployed HA resource. The editor reads this directory's `dashboard.json`, lists individual room lights, primary devices, appliances, doorbell cameras, and thermostats whose entity IDs start with the room ID. It does not include room-wide light groups, scenes, or the unassigned portable lamp, and never calls HA.

Run from the repository root, binding to loopback or a trusted private LAN/Tailscale address only. The editor has no authentication; do not expose it publicly:

```sh
python3 docs/operations/house-dashboard/placement_server.py --bind 127.0.0.1 --port 8766 --output .amp/in/house-atlas-placements.json
```

Choose a floor and room, select a device, then tap its location in the focused map. Drag pins to adjust, or focus the map and use arrow keys (Shift moves five units). Whole floor is for room navigation. Unplace and Undo edit the draft; **Save placements** persists it on the server, and **Download JSON** exports a copy. Unsaved edits stay in the page, not across reloads. A stale browser cannot overwrite a newer save; download its draft before reloading to resolve a conflict.

The saved JSON maps entity IDs to `{floor, room, x, y}` in the existing floor plan's SVG coordinates, independent of screen size or room zoom. Door-edge placements may cross a room outline but must stay inside the floor bounds. Copy the approved positions into the card's `placements` in `dashboard.json`; saving in the editor does not apply them to House Atlas. The output under `.amp/in/` is local, not versioned; retain it until the placements are incorporated.

### Icon studio

`icons.html`, served at `/icons`, assigns symbols to the 28 mapped lights. Its map uses the versioned, aligned placements and cannot move them. A new icon save starts with best-effort choices from HA device models and fixture names; existing saves are never reseeded. The selected light shows the evidence or assumption behind its initial choice. All 27 light shapes are available for every light, in a consistent order, including a bare bulb, chandelier, and repo-owned full-height shade silhouette. The eight basement lights are confirmed bare bulbs. Search filters only by the user's text, never an inferred fixture category. Clear, Undo, Next light, and Download JSON support review. Overlapping map markers remain independently selectable in the device list. Unsaved choices are lost on reload; concurrent saves use the placement editor's revision protection.

Build the catalogue from pinned upstream revisions, then enable the editor with both icon arguments:

```sh
python3 docs/operations/house-dashboard/icon_catalogue.py .amp/in/icon-catalogue.json
python3 docs/operations/house-dashboard/placement_server.py --bind 127.0.0.1 --port 8768 --output .amp/in/house-atlas-placements.json --icons-output .amp/in/house-atlas-icons.json --icon-catalogue .amp/in/icon-catalogue.json
```

The catalogue retains SVG geometry and attribution; Material Design Icons uses Apache 2.0, and Hue Icons uses CC BY-NC-SA 4.0. No icon pack is installed in HA. The separate save maps entity IDs to names such as `mdi:floor-lamp` or `hue:signe-gradient-floor`; saving does not change placements, dashboard configuration, or physical devices. The approved choices are copied to each light placement's `icon` in the versioned dashboard. The editor has the same private-network-only restriction as the placement studio.

### Browser checks

`house-atlas.test.js` exports `checkMapControls(card, hassFixture)` for a disconnected browser preview at desktop or phone width, with the versioned dashboard and representative entity states/registry. It intercepts `callService`, exercises the rendered controls, asserts exact light/script/lock/cover payloads, and restores the supplied fixture afterward. It checks tap versus hold, movement/cancellation, right-click, keyboard context and focus restoration, brightness/color commits, scene scripts, unavailable lights, ambiguity-only zoom and hold, camera-first door controls, and garage toggle while moving. Do not run it against a live dashboard.

Also inspect light/dark whole-floor and focused layouts, narrow light dialogs, scene overflow, all four floors, collision targets, and non-light HA details. Layout uses available width; hover styling uses pointer/hover capabilities, never user-agent device detection. Reference: [MDN pointer media feature](https://developer.mozilla.org/en-US/docs/Web/CSS/@media/pointer) and [WCAG enhanced target size](https://www.w3.org/WAI/WCAG22/Understanding/target-size-enhanced.html).
