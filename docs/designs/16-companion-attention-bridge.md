# Companion attention bridge

## Status

Draft

## Decision Summary

Add a generic `glimpseui:attention:*` event contract on pi's in-process `pi.events` bus
so any extension can signal "this session is blocked waiting on the user." The
`glimpse-companion` extension acts as the sole bridge: it translates these events into
its existing Unix-socket protocol and renders a distinct flashing pill. The permission
gate is the first consumer. The key tradeoff is decoupling — emitters never touch the
companion socket or its status vocabulary, at the cost of one extra correlation-id hop
to make span resolution race-safe. Events are namespaced under `glimpseui:` to avoid
bus collisions; this is a deliberate, minor naming coupling — emitters reference the
namespace string but nothing else about glimpse.

## Problem Statement

The glimpse companion follows the cursor and shows per-session agent activity. When the
permission gate calls `await showPermissionGate(...)`, the agent loop blocks until the
user answers in the TUI. If the user is looking elsewhere, nothing on the companion
indicates that a session is stalled waiting for input. The companion is click-through
and follows the cursor, so it can only ever be a notification surface — but a flashing
"needs you" pill is exactly the missing signal.

We also want this to generalize: any future extension that blocks on the user (not just
the permission gate) should be able to raise the same callout without learning the
companion's socket protocol.

## Goals

- Surface a distinct, attention-grabbing companion state when a session is blocked on the user.
- Keep emitters decoupled: they emit a semantic event, nothing more.
- Make the companion the single owner of the socket and of rendering decisions.
- Handle overlapping and stale spans without corrupting unrelated state.
- Degrade to a no-op when the companion is disabled or unsupported.

## Non-Goals

- Making the companion interactive. It stays click-through and notification-only.
- Cross-session or cross-process attention. The bus is per-session; the companion
  already multiplexes sessions by id over its socket.
- Replacing the permission gate's TUI prompt. The actual decision still happens in the TUI.

## Design Decisions

### 1. Semantic `glimpseui:attention:*` events, not a glimpse-shaped passthrough

Emitters publish domain intent, not presentation. Events are namespaced under
`glimpseui:` to avoid collisions on the shared bus:

```ts
pi.events.emit("glimpseui:attention:request", {
  attentionId,            // UUID (crypto.randomUUID), generated by the emitter
  kind: "permission",     // semantic category; companion maps kind -> rendering
  detail,                 // optional short context (e.g. the command/rule label)
});

pi.events.emit("glimpseui:attention:resolve", { attentionId });
```

The companion owns the `kind -> {status, color, label, glyph}` mapping. The `kind` stays
presentation-agnostic; only the namespace prefix references glimpse. Emitters never
import glimpse, never learn the socket path, and never name a status string. Adding a
new attention category later is a one-line map entry in the companion, and any extension
gets the callout for free.

### 2. The permission gate emits on `pi.events` only

`permission-gate` gains no glimpse dependency beyond the namespaced event string. It
wraps its blocking prompt:

```ts
const attentionId = randomUUID();
pi.events.emit("glimpseui:attention:request", { attentionId, kind: "permission", detail: subject.detail });
try {
  const decision = await showPermissionGate(ctx, prompt.title, prompt.body);
  // existing allow / allow_with_note / reject / block branches unchanged
} finally {
  pi.events.emit("glimpseui:attention:resolve", { attentionId });
}
```

The `finally` guarantees resolution on every branch, including `reject` with `abort`
(which defers `ctx.abort()` via `setTimeout`, so the resolve still fires first).

### 3. UUID correlation ids make resolution race-safe

`attentionId` is a `crypto.randomUUID()` value. Enforcing UUIDs guarantees global
uniqueness across every emitter and session, so no two spans can ever collide on the
shared bus — the bridge's outstanding-id set needs no namespacing by emitter.

The companion bridge keeps a per-session `Set<attentionId>` of outstanding spans:

- `glimpseui:attention:request{id}` — add `id`. If the set was empty, snapshot the current
  companion status, then send the `awaiting` status over the socket.
- `glimpseui:attention:resolve{id}` — `delete id`. If the set is now empty, restore the
  snapshotted pre-attention status (the blocked agent loop will repaint to its real status
  on the next `tool_execution_start` / `agent_end`).

Consequences:

- A resolve for an unknown or already-removed id is a no-op (`Set.delete` returns false).
  This directly answers the stale-resolve race: it cannot wipe an unrelated, still-active
  attention.
- Overlapping spans (two emitters, same session) only clear the pill when the **last**
  outstanding id resolves.

### 4. Notification-only rendering: purple, pulse, and glyph

The companion gets a new `awaiting` status rendered differently from `error`:

- A purple color (e.g. `#A855F7`), a CSS pulse/flash animation, and a leading glyph
  (e.g. `▲`) plus label "Needs you". Note `searching` already uses purple `#8B5CF6`, so
  `awaiting` picks a distinct purple; the pulse animation and glyph further separate the
  two states visually.
- This is the only `companion.mjs` change: a `STATUS_COLOR`/`STATUS_LABEL` entry and a
  keyframe animation applied when the row's status is `awaiting`.

### 5. Respect the existing enable/support gate

The bridge subscribes to `glimpseui:attention:*` unconditionally but forwards to the
socket only when the companion is `enabled` and `followCursorSupport.supported` — the same
guard the existing status handlers use. When disabled, the events are dropped and the
outstanding-id set is never populated, so there is nothing to leak.

## Edge Cases & Failure Modes

- **Stale resolve:** resolve for an id not in the set is a no-op. Handled by the id set.
- **Leaked span (emitter crashes before resolve):** the bridge also clears its
  outstanding-id set on `agent_end` / `turn_end` / `session_shutdown` as a backstop, so a
  never-resolved span cannot pin the pill forever.
- **Companion enabled mid-span:** request was dropped while disabled; the pill simply
  never shows for that span. Acceptable — no corrupted state.
- **Overlapping attentions on one session:** tracked by distinct ids; pill clears only
  when the set empties.
- **Reject + abort:** `finally` emits resolve before the deferred `ctx.abort()` runs.
- **No subscriber (companion extension not loaded):** `pi.events.emit` with no listener
  is a no-op.

## Rejected Alternatives

### Generic `glimpseui:status` passthrough

Have emitters emit the exact status string the companion renders. Rejected: it couples
every emitter to the companion's vocabulary and socket semantics, defeating the goal of a
reusable, presentation-agnostic signal.

### permission-gate writes to the companion socket directly

Skip the bus and have the gate open the socket itself. Rejected: two extensions owning
the socket protocol and path, duplicated connect/spawn logic, and no reuse path for other
emitters.

### Model `awaiting` as an additive overlay in the renderer

Render attention as a separate visual element alongside the normal status instead of
overwriting the row status. Rejected as over-engineering for v1: the agent loop is blocked
during a permission prompt, so nothing else is updating that row, and overwrite+restore is
sufficient and simpler.

## Integration Points

- **`pi.events`** (`core/event-bus.ts`): in-process, per-session `EventEmitter` shared by
  all extensions loaded in the session. Carries the `glimpseui:attention:*` contract.
- **`glimpse-companion/index.ts`**: adds the `glimpseui:attention:*` subscription, the
  outstanding-id set, the status snapshot/restore, and the socket `send("awaiting", ...)`.
  Reuses existing `send()`, gating, and `SESSION_ID`.
- **`glimpse-companion/companion.mjs`**: adds the `awaiting` color/label and pulse keyframe.
- **`permission-gate/index.ts`**: wraps `showPermissionGate` with request/resolve emits.
- Both extensions are deployed via chezmoi under
  `chezmoi/private_dot_pi/agent/extensions/`; lint with `uv run poe lint:pi`.
