# Container platform desired state

## Question

Decide how native mise owns Docker and deploys services: repository and package policy, daemon settings, operator access, config-tree identities, Compose rendering and validation, image pull policy, secrets, dependencies, health checks, rollback, per-stack partial reconciliation, and retirement. Replace the old macvlan assumptions with the decided host-network model.

Audit the `docker_stack` role and its move-day fixes, but do not translate its implementation by default. Close with a deployment interface and smoke-test contract; then create a separate implementation ticket.

## Resolution

Grilled 2026-09-07 against the old `docker_stack` role, retained Compose definitions, the running Debian host, and the accepted host-network contract. Native mise installs Docker CE stable from Docker's official apt repository, including Engine, containerd, Buildx, and the Compose plugin. Host package policy owns those package upgrades. Docker and containerd start at boot; Docker uses rootful operation, `live-restore`, the `json-file` log driver capped at three 10 MB files, and Docker-managed firewall rules. `thurstonsand` joins the `docker` group. The Unix socket is the only operator API; no TCP daemon listener is permitted.

Docker keeps disposable runtime state, images, and layers on the boot SSD under its default ext4-backed paths. Durable application state lives under `/mnt/black-box/docker/<service>` and media under `/mnt/ark/media`; the boot disk may also hold replaceable caches and build artifacts. This preserves the useful distinction: reinstalling or replacing the boot SSD recreates the platform from Git and registry images, while ZFS contains state worth preserving and snapshotting. Do not put overlay2 directly on ZFS, select Docker's native ZFS driver, or introduce a runtime zvol without a measured need. If runtime capacity becomes constraining, the escape hatch is a larger boot SSD.

The target declares Docker's address pool as `10.42.0.0/16` allocated in `/24` networks, leaving `10.43.0.0/16` to Incus. Compose projects use private bridges and NAT, plus one explicitly shared ingress network. There is no host bridge or macvlan. Only Caddy's host ports 80 and 443 and Plex's 32400 may be published. Local traffic resolves an exact service hostname to `10.10.10.42`, crosses UniFi policy, terminates TLS at Caddy, and reaches a service alias over the ingress network. Selected public traffic terminates TLS once at Cloudflare, travels through the outbound tunnel as HTTP to cloudflared, crosses the private ingress network to Caddy's unpublished HTTP listener, and then reaches the same service alias. Plex retains its direct router-forwarded path on 32400.

Docker service startup is ordered after `/mnt/black-box/docker` and `/mnt/ark/media` so an absent ZFS mount cannot silently receive writes beneath its mountpoint. This ordering is declared and checked rather than exhaustively failure-tested before useful services return. Application processes use image defaults first. Images supporting `PUID`/`PGID` run as UID 1000 (`thurstonsand`) with shared media GID 3000; Plex's retained state is recursively aligned to `1000:3000`. Images with fixed identities or root-owned initialization are explicit per-stack exceptions. Adapt ownership only on the exact persistent paths a service consumes; do not blanket-chown imported state. `thurstonsand` also joins the `media` group.

Source stacks move from `ansible/stacks` to `bootstrap/targets/pod042/containers/stacks`. Native mise files install each Compose definition and private interpolation environment under `/etc/ansiblonomicon/containers/<stack>`, while `[bootstrap.compose]` owns project lifecycle, model-hash convergence, health, pulls, recreation, and retirement. Compose owns each project's internal dependencies, health ordering, networks, and service lifecycle. There is no cross-project dependency expansion, no global `container_name`, and no per-stack systemd unit. Stable project names and network aliases provide identity. Services normally use `restart: unless-stopped`, and no default CPU or memory limits are imposed.

Each `[bootstrap.compose.<project>]` declaration is the lifecycle manifest. A project is `running`, `stopped`, or temporarily `absent`; once an absent project has converged away, its declaration and managed files are deleted. Manual removal remains an operator choice. Secrets normally enter through mode-`0600` managed environment files and `${VAR}` interpolation. Rendering a secret is allowed when an image requires it. Home-lab inspection exposure is accepted; consistency is preferred over image-specific secret mechanisms without a concrete benefit.

`mise pod042 containers [--check]` is the local/remote guarded operator interface. Native mise plans every declared project with the rest of the host resources, then applies them serially and fail-fast through Docker Compose with pull, build, recreation, wait, and orphan policy declared per project. Mise compares each running container's canonical Compose config hash to the installed model. Compose may remove its own orphans and project networks. Reconciliation never runs broad image, system, or volume pruning or deletes bind-mounted data automatically.

Watchtower is a resident Compose service with a daily 04:00 update schedule, dependency-aware ordering, Hark reports for updates and failures, and no no-change spam. It updates every running registry-backed container, including Plex and itself, while locally built or unpullable images are explicitly excluded. The declared image reference remains the update boundary: Watchtower follows that exact tag/channel and does not interpret semantic version ranges. Cleanup is enabled. Watchtower cannot retain the last N images or delay cleanup, so rollback redownloads an earlier image and application-data rollback remains manual. Update-on-start is disabled.

Docker-socket consumers are narrow, explicit exceptions: the operator, Watchtower, the torrent project's namespace repair service, a later Pascal agent, and monitoring through the least-capable practical socket proxy. The torrent repair service continuously recreates only `network_mode: service:gluetun` dependents stranded when Gluetun restarts or is replaced; Watchtower ordering alone cannot cover VPN lifecycle outside Watchtower. No global autoheal loop is introduced; repeated blind restarts conceal faults.

Native Netdata is the initial observability single pane of glass, chosen over Beszel, Uptime Kuma, and Gatus for combined host, ZFS, systemd, Docker, log, alert, basic endpoint, anomaly-correlation, and official local MCP support. It reports actionable alerts to Hark, connects outbound to Netdata Cloud for the operator dashboard, and remains exposed directly through Caddy only to trusted local networks or VPN, not through the public Cloudflare tunnel. Agent-assisted diagnosis starts human-invoked; no automatic remediation or alert-triggered agent execution is authorized. Netdata answers whether observed services are healthy. Native mise Compose status separately answers whether declared state landed as part of each reconcile plan; it is not a timer, dashboard, or second alert producer. Gatus may be added later only if Netdata's endpoint checks prove insufficient.

[Implement the pod042 container platform](45-implement-container-platform.md) first installs the engine, daemon policy, mount ordering, operator access, networks, native Compose declarations, Watchtower, Netdata, and a disposable canary without starting preserved applications. Acceptance proves install, Compose validation, canary deploy and health, synchronous declared-state verification, and clean canary retirement. Reboot, deliberate mount loss, and a synthetic Watchtower update are deferred in favor of restoring useful services quickly. One week after real registry-backed services begin running, an operator spot-check should confirm Watchtower has observed and applied an actual update. After the canary passes, retained Compose projects may proceed in parallel one project per thread; the parent integrates their declarations and shared ingress.
