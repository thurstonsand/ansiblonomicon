# Bunker Rebuild

## Destination

The NAS reborn as a plain Debian 13 host (substrate decided in ticket 05; "Proxmox" in early ticket titles is historical): existing ZFS pools imported intact, all surviving services running (Plex with QuickSync transcoding, the docker stacks, shares), the agent platform running with full host resource sharing via incus, all declared from this repo. Execution is in scope: the map ends when the rebuilt machine is running at the new house.

## Notes

- Execution tickets are allowed (charted 2026-08-19; overrides wayfinder's plan-only default).
- Timing: physical move ~2026-08-26. Extended downtime is acceptable; the smart home restarts fresh regardless.
- Skills to consult: `truenas-docker-ops` while the old host still runs; `installing-software` for anything landing on managed machines; `/grill-me` for grilling tickets.
- Hardware (verified 2026-08-19): i5-12600K (10c/16t), 96G RAM, UHD 770 iGPU (`/dev/dri` present, feeds Plex as a shared container device today). `capacity` = 4×~14T raidz1 + hot spare (30.2T used; 12T media in `watch`, 5.2T storj). `performance` = 2×1T NVMe mirror (docker configs, apps). Single 448G boot SSD. SATA on Intel PCH + ASMedia ASM1062, no HBA; NVMe behind Intel VMD (BIOS toggle to review before install).
- Standing decisions from charting:
  - **Drop TrueNAS entirely.** The host owns ZFS, shares, and services directly. No TrueNAS VM, so no HBA purchase. `local.truenas` retires in favor of plain Debian roles (sanoid, smartd, zed, samba). (Originally "bare Proxmox" with `community.proxmox`; ticket 05 later decided plain Debian + docker + incus.)
  - **Pools import, they don't migrate.** TrueNAS pools are standard OpenZFS; a fresh Proxmox install touches only the boot SSD, then `zpool import`. Both `capacity` and `performance` (docker configs included) survive as-is. No partitioning or compressing of data.
  - **Retire**: storj node (graceful exit starts before the move — bleed-off time), HAOS VM + datasets, scrypted stack, openclaw VM (declared dead 2026-08-19 during ticket 13 sign-off — not coming back; its `*-ssh` tunnel hostname and DNS record go with it).
  - **Single boot SSD stays.** Recovery is reinstall + playbook; nothing valuable lives on the boot disk as long as host config stays declarative.
  - **Safety net**: cloud-backup the irreplaceable subset only; the media is re-acquirable by design.
  - Agent platform direction: LXC-style full host resource sharing (caps, not reservations — the 2c/8G OOM problem is a VM artifact). Inspiration from Amp orbs; durable rather than ephemeral, but cheap provision/destroy is worth exploring.
  - Name origin: proposed by 2B, chosen by Thurston — the Bunker is command infrastructure, rebuilt.

- [Pool fresh start and permissions reset](tickets/10-pool-fresh-start.md) — Keep pools (verified clean at pool level), rebuild all datasets fresh; rename to `ark`/`black-box` at import; raidz1 + hot spare stays, no encryption, no drive purchases; two-tier POSIX permission model (per-image config uids + shared `media` gid 3000 via setgid + `group_add`), spike-proven in OrbStack.
- [Cloud backup replacement](tickets/04-backup-replacement.md) — restic + Backblaze B2, fresh repos; rule: `black-box` backs up offsite (~20–50G, docker configs + agents + anypod db), `ark` is re-derivable via the *arr databases; 7d/4w/12m retention; alerting deferred to ticket 12. Executed: device backups retired (1.15T freed), cli-proxy-api's 282G log leak fixed at the source.
- [Alerting platform landscape](tickets/11-alerting-platform-landscape.md) — Shortlist: Hark + hosted Healthchecks.io (recommended spike), Pushover + Healthchecks.io, or hosted ntfy + Healthchecks.io; self-hosting the alerter on the monitored host bounded as an anti-pattern. Decision belongs to [Alerting and notifications](tickets/12-alerting-decision.md), now unblocked.
- [Alerting decision](tickets/12-alerting-decision.md) — **Hark + hosted Healthchecks.io, spike-proven live** (direct push, HC down→up webhook cycle, prompt iPhone delivery). Producer contract: scheduled jobs ping HC `/start`→`/<exit>`; event producers POST Hark via the `storage-alert` shim; one host-alive heartbeat; notification failure never masks job failure; URLs via systemd credentials from `op`. Discord webhook retires. Approvals-for-pascal is Pro-gated — decided at ticket 07 execution. Credentials live in the `agent` vault; HC integration + API key already provisioned.
- [Storage services](tickets/08-storage-services-on-bare-proxmox.md) — One SMB share (`media`, admin-tier, force-group media), no NFS, no Time Machine. Sanoid: black-box hourly=24/daily=7/monthly=1; ark deliberately bare. Scrubs as staggered timers, smartd on today's cadence, zed (the hot-spare reflex) — all through one `storage-alert` shim awaiting ticket 12. No storage UI. Repo shape: one `pod042.yml` playbook replaces truenas.yml + the VM playbook; `local.truenas` retires; `lan:` migrates.
- [Raw TCP auto-expose](tickets/18-raw-tcp-auto-expose.md) — Research closed: WARP CIDR routing (incus bridge subnet through the existing tunnel + admin-only local L3 route) is the only near-zero-per-service shape; ssh forwarding is the baseline until then; caddy-l4 bounded to a narrow direct-TLS opt-in (postgres needs `l4postgres`, MySQL impossible, redis needs SNI). Cert correction folded into ticket 07: `<port>.<instance>` needs per-instance wildcards. Spike (WARP/Gateway route) may be chartered post-cutover.
- [Agent platform](tickets/07-agent-platform-on-proxmox.md) — **Host = pod042** (`poe pod042` becomes the host reconcile; "bunker" stays this effort's codename). Durable agent instance = **pascal** (all five trust grants: host docker socket, incus socket, pool mounts, host ssh, nesting) + narrow-envelope `w-<project>` workers from an ansible-declared profile. Reachability: port-subdomain caddy route `<port>.<instance>.thurstons.house`; ProxyJump for raw TCP. Old pod042 VM dies at cutover; its map closed as superseded. Follow-up seeded: Cloudflare Access wildcard external expose. Execution item: purge openclaw + stale-pod042 references repo-wide.
- [Service runtime topology](tickets/05-service-runtime-topology.md) — **Substrate: plain Debian 13 + docker + incus — not Proxmox.** Docker on its supported platform; incus provides the agent platform (caps, ephemerals, profiles) and occasional VMs through one API. Network: bridges + one caddy on 443 (hostname routing, DNS-01 certs, `remote_ip` per tier), wildcard DNS → bunker; host ports only 80/443/32400. All 11 stacks + plex carry over; ddclient reprieved (feeds Cloudflare Access home-IP bypass). Unblocks ticket 07; the map's "on Proxmox" phrasing is now historical.
- [VLAN security redesign](tickets/13-vlan-security-redesign.md) — Six-network model: infra / admin / household / discovery / appliances / VPN. Bunker on one access port in infra, per-host containment (macvlan, trunk, and External VLAN all dissolve); one caddy on shared 443 with hostname routing; deliberate mDNS reflection (admin+household↔discovery) replaces the unfiltered reflector. openclaw declared dead at sign-off. Implementation via tickets 15 and 09.
- [UDMP declarative rebuild](tickets/15-udmp-declarative-rebuild.md) — Ownership split: OpenTofu + `ubiquiti-community/unifi` owns controller lifecycle (networks, ZBF policies, forwards, SSIDs, DNS); ansible keeps the router-OS layer (nextdns, querier — to be made blank-router-complete); manual remainder: mDNS scope, console bootstrap, adoption. Wipe sequenced AFTER the new WAN is up; fresh config bypasses (not cures) the legacy ZBF migration; `WAS-110` static route is critical-path or internet dies. Execution ticket must pin/spike the provider against the live Network release (local API is already 10.5.67 vs 9.x public contracts).
- [UDMP network audit](tickets/14-udmp-network-audit.md) — Current state mapped live: 4 VLANs (2 macvlan networks empty on paper), zone-based firewall already on (23 custom policies; 7 dissolve onto the bunker, 4 provably dead, 3 can never match), inbound surface is only plex 32400 + storj 28967 (retiring) + xbox. `storj.thurstons.house` is not an exposure — it feeds Cloudflare Access's home-IP bypass via terraform. The one thing caddy can't express: egress blast-radius containment for the internet-published set (External VLAN's whole purpose). Ticket 13's real problem is the overcrowded Default VLAN, not the containers.
- [Backup solution landscape](tickets/03-backup-solution-landscape.md) — Shortlist: restic + Backblaze B2, borg + Hetzner Storage Box, or sanoid/syncoid to a friend's ZFS host; rsync.net priced out ($125/mo, 10T minimum), zfs.rent ruled out for simplicity. Decision belongs to [Cloud backup replacement](tickets/04-backup-replacement.md), now unblocked.
