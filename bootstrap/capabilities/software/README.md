# Mac software

Codex CLI on pod153 reconciles through `mise codex` and the laptop software pass. Its official installer selects the latest stable standalone release at `~/.local/bin/codex` on every apply. T3 Code discovers that executable through its service PATH and reuses the existing ChatGPT login in `~/.codex`; enrollment with `codex login` is a one-time step, not managed credentials. Use `mise codex --check` to preview installation without changing the host.

On the work Mac, `Brewfile.work` installs the CLI, and `mise codex` comes from `bootstrap/targets/ML-DFC6YK6VJQ/mise.software-codex.toml` instead. The app-server daemon runs its own copy of the Codex package, refreshed only by the standalone updater, which can't reach its download there. When that copy's version differs from the CLI's, the task runs `codex app-server daemon update --from-cli --yes`, which copies the Homebrew package into place and pins it.

This capability installs small Mac tools at stable executable paths. Claude Code installs through its official installer when absent, then runs `claude update` on every apply. T3 Code moved to the [t3 capability](../t3/README.md). Cua Driver installs only when absent, then follows its stable channel with `cua-driver update` on every apply and refreshes the skill pack the agent-harness catalogue copies, removing the pack's own agent links so profile scoping decides which harnesses receive it. The in-repo Go program retains daily dependency maintenance while mise's content-aware task cache owns build freshness. Work's Pi uses mise's GitHub backend and normal release-age policy, retaining the full release tree behind the stable libexec link.

Host reconciliation runs the Go project's own `install` and `deps:update` tasks with `--skip-tools`, preserving the host-owned Go already on `PATH` and never installing developer tooling. Running those tasks directly in a project still uses its declared Go and golangci-lint versions.

`uvc-util` deliberately uses a narrow Git adapter. Mise's repository resource rejects the generated overlays this checkout must retain, and its `main` ref does not always fetch a newly advanced remote tracking branch. The adapter preserves untracked files, rejects tracked dirt, origin changes, and divergence, and only fast-forwards fetched `origin/main`. The three first-party overlays and `~/.local/bin/configure_camera.py` link to the canonical role sources; the executable bit lives on `configure_camera.py` itself, and resolving that link keeps `camera_settings.json` adjacent. Native task source hashing owns rebuilding; reconciliation never runs camera settings. UVC file deployment also applies the capability's `state = "absent"` retirements in `mise.files.toml`, currently the retired `sessions` binary and its maintenance stamps.

Checks report planned changes without applying them. Pi checks query release availability; UVC checks use `git ls-remote` without fetching. If the remote commit is absent locally, the check reports the changed ref but cannot prove ancestry until apply fetches it. Invalid repositories and failed discovery still fail the check.

Run `mise berkeley-mono` on either Mac, or `mise docker-context` or `mise cua-driver` on pod153; add `--check` for a read-only preview. Berkeley Mono reconciliation checks the four licensed OTF destinations before contacting the original personal 1Password account, checks all four archive members and their OpenType signatures before atomically installing only missing files, and never stores the archive in the repository. The Docker context adapter preserves unrelated contexts and Docker configuration while declaring `pod042` as `ssh://pod042`, with that context selected persistently. Both adapters leave converged state untouched.

`mise docker-credentials` stores the work Artifactory identity in Docker's credential store for each registry listed in the work target's private `artifactory_docker_registries`. Apply reads the username and identity token from the 1Password `Artifactory` item through `fnox-host` and writes a registry's credential only when the stored one differs, so rotating the token in 1Password and reconciling replaces an expired login. Check reads no 1Password credentials; it reports only registries with no stored credential and cannot detect a stale one.
